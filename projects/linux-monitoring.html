PROJECT 02

Linux Server Operations Lab

A two-server virtual lab focused on installation, secure access, services, logs, storage, monitoring, patching, and controlled recovery.

Ubuntu ServerVirtualBox/VMwareSSHSystemdLogsMonitoringPlanned — update after completion

Objective

Build two Linux virtual machines: one application server and one monitoring/log server. Establish secure administration, document normal operating state, monitor resources, and recover from intentionally created failures.

Why this matters

Technicians need to distinguish hardware, operating-system, storage, service, and network symptoms. Linux logs and service tools provide concrete evidence that you can investigate instead of guessing.

Lab design

  • Two Ubuntu Server VMs on an isolated or host-only network with static or reserved addresses.
  • SSH key authentication, a non-root admin account, and host firewall rules.
  • A simple service such as Nginx on the application server.
  • System health checks for CPU, memory, disk, interface state, services, and recent errors.
  • Centralized logging or a lightweight monitoring stack; keep the first version simple and understandable.
  • A backup and restore test for one configuration file and one service.

Build sequence

  1. Create the VM plan: names, CPU, memory, disk, network, IP addresses, and purpose.
  2. Install the operating system and record installation choices.
  3. Create users, configure SSH keys, apply updates, set time synchronization, and configure the firewall.
  4. Install and validate the test service.
  5. Configure basic health monitoring and define normal thresholds.
  6. Create failures: stop the service, fill a small test filesystem, change a firewall rule, and misconfigure name resolution.
  7. Use logs and commands to identify root cause, recover service, and record the incident timeline.
  8. Capture final state, package configuration files, and write a runbook.

Acceptance tests

  • SSH works with keys and direct root login is not required.
  • The application service starts automatically after reboot.
  • Monitoring or scripted checks report service, CPU, memory, disk, and network status.
  • A stopped service and low-disk condition are detected and resolved.
  • A backed-up configuration can be restored and validated.

Resume bullet — use only after completion

Built and operated a two-node Linux lab with secure SSH administration, service management, host firewall controls, health monitoring, log-based troubleshooting, and tested configuration recovery.

Evidence checklist

  • VM architecture diagram
  • Build notes with versions and resource settings
  • User and SSH configuration summary
  • Firewall rule list
  • Service status and log excerpts
  • Monitoring screenshot or health-check output
  • Backup/restore proof
  • Recovery runbook
