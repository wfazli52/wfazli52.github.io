PROJECT 01

Enterprise VLAN & Routing Lab

A small enterprise network that proves you can turn requirements into a topology, configure core services, validate connectivity, and document the result.

Cisco Packet TracerVLANsRoutingDHCPDNSACLsPlanned — update after completion

Objective

Design and configure a two-switch, one-router or multilayer-switch network for four departments: Operations, Engineering, Guest, and Management. Separate traffic with VLANs, assign subnets, automate client addressing, and restrict access with clear policy rules.

Why this matters

Data center technicians routinely trace links, verify addressing, isolate layer-1 through layer-3 faults, replace network components, and communicate exact test results. This project creates evidence of that troubleshooting discipline.

Lab design

  • Two access switches and one routing device; add a second switch uplink for trunking practice.
  • Four VLANs with a written purpose, subnet, gateway, DHCP scope, and reserved-address range.
  • At least eight client devices plus one server providing a simple DNS or web test service.
  • One ACL requirement, such as Guest users reaching the test web service but not the Management subnet.
  • A topology diagram, port map, IP address plan, configuration backup, and test matrix.

Build sequence

  1. Write requirements first: users, departments, allowed traffic, naming standard, and success criteria.
  2. Create the IP plan and confirm that every subnet has enough usable addresses.
  3. Build and label the physical and logical topology in Packet Tracer.
  4. Configure access ports, VLANs, trunks, gateways, and routing.
  5. Configure DHCP and DNS, then verify leases and name resolution.
  6. Apply the ACL and test both permitted and denied traffic.
  7. Introduce three faults—wrong VLAN, bad gateway, and disabled interface—then document how you isolate each fault.
  8. Export configurations and complete the project write-up.

Acceptance tests

  • Every client receives the correct address, mask, gateway, and DNS server.
  • Clients can reach permitted destinations across VLANs.
  • Guest-to-Management traffic is denied while the approved service remains reachable.
  • DNS resolves the lab hostname to the correct IP address.
  • The test matrix contains expected result, actual result, evidence, and final status for every test.

Resume bullet — use only after completion

Designed and validated a segmented Cisco lab network with four VLANs, inter-VLAN routing, DHCP, DNS, and access-control policy; documented topology, IP addressing, configurations, and fault-isolation tests.

Evidence checklist

  • Final Packet Tracer file (.pkt)
  • Topology screenshot with device and port labels
  • IP address plan
  • Sanitized device configurations
  • Completed test matrix
  • Three troubleshooting notes
  • A 60–90 second walkthrough video or GIF
